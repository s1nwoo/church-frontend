# 관리자 윷놀이: 수동 배치와 빔 화면

- 관리: `/admin/yut`
- 빔 화면: `/admin/yut/display`
- 두 경로 모두 기존 AdminRoute 아래에서 관리자 계정만 접근한다.

## 현장 사용

1. 팀전(2~4팀, 팀마다 말 2~4개) 또는 개인전(2~10명, 한 사람당 말 1개)을 선택한다. 이름과 중복되지 않는 색상을 설정한다.
2. 실제 윷을 던지고 관리자 화면의 말 목록 또는 판 위 말을 선택한다.
3. 놓을 칸을 클릭한다. 도·개·걸·윷·모 입력이나 이동 거리/턴 제한은 없다.
4. 같은 팀 말은 업히고 상대 말은 자동으로 대기석으로 돌아간다.
5. 업힌 말은 항상 함께 이동한다. 입체적으로 쌓인 말과 이동·잡기 효과가 두 화면에 표시된다.
6. 완주는 왼쪽 같은 팀 완주 공간, 대기는 오른쪽 같은 팀 대기석으로 드래그한다. 완주한 말은 왼쪽 완주 공간에서 다시 끌어올 수 있다.
7. '말 배치 되돌리기'는 직전 이동과 함께 이동하거나 잡힌 말까지 원상 복원한다.
   말 선택 자체는 이력에 남지 않는다. 최근 100회 배치는 새로고침해도 유지된다.
8. '빔 화면 열기'로 별도 창을 열고, 디스플레이 확장 모드에서 프로젝터 쪽으로 옮긴 뒤 전체 화면을 누른다.
9. ‘한 명 더!’와 ‘처음으로!’ 표식을 발판으로 끌어 놓아 각각 한 칸씩 설정한다. ‘한 명 더!’ 칸에 도착하면 관리자가 합류할 대기 말을 선택하며, ‘처음으로!’ 칸에 도착하면 이동한 말이 전부 대기석으로 돌아간다. 설정과 효과도 되돌릴 수 있다.

빔 화면은 읽기 전용이다. 관리자와 같은 브라우저/사이트에서 열어야 하며 다른 PC로 전송하지 않는다.
관리자 창은 한 개를 사용한다. 브라우저 저장소 이벤트와 BroadcastChannel로 변경사항을 즉시 전송한다.
설정 중에는 설정 내용을 읽기 전용으로 공유하고, 경기 시작 후 윷판으로 전환한다. 경기 중에는 보드·완주 공간·참가자 현황과 관리자가 선택한 말을 함께 표시한다.

## 구조

- `boardModel.js`: 29개 칸의 좌표와 접근성 이름.
- `engine.js`: 순수 수동 배치·업기·잡기 처리.
- `storage.js`: 저장 형태 검증, 기존 v1 경기의 말 위치 마이그레이션.
- `useYutGame.js`: 최대 100회 배치 스냅샷, 새로고침 복원, 창 간 동기화.
- `Board.js`: 참고 이미지의 사각 테두리, 원형 칸, 중앙 태극 형태와 말 렌더링.
- `PieceControls.js`, `TeamSummary.js`: 관리 조작과 공유 현황.
- `YutPage.js`, `YutDisplayPage.js`: 관리자·빔 화면.
- 글꼴은 홈페이지 공통 `A2z`, `Pretendard` 순서로 사용한다.

경기는 브라우저 저장소에만 남으며 운영 DB/API에 기록하지 않는다.
새 경기로 확정하면 이전 경기/되돌리기 이력이 초기화된다.
외부 아이콘이나 새 글꼴 의존성은 추가하지 않았다.

## 검증

`npm test -- --watchAll=false --runInBand`, `npm run build`.
실제 관리자 인증과 운영 데이터 연동은 루트의 local-start.cmd로 실행한다.

인증과 별도의 UI 검토: `node scripts/preview-yut.cjs` → `http://127.0.0.1:3107`.
같은 미리보기 서버에서 빔 화면 창도 연다. qa 진입점은 운영 번들에서 사용하지 않는다.
